Guidelines

The rules from the Figma Rules page, examples of using them well, and the behaviour developers need to build.

Rules

Mandatory rules apply to every design and every widget; recommended rules apply unless there is a clear reason. New rules are added as numbered entries, and existing numbers never change, so “Rule 007” always means the same thing.

001

Screen background Mandatory

The main/root screen background is always bg/screen: solid white #FFFFFF in Light mode (#0D1117 in Dark). Cards and sheets sit on top of it; this rule covers the root screen only.

002

Use tokens, never raw colours Mandatory

Designs and components use Color tokens (bg/, text/, border/, icon/, primary/, status/). Never pick a primitive (blue/600, neutral/300…) or type a hex. This is what makes Dark mode and future rebrands work.

003

Even values only Mandatory

Font sizes, line heights, spacing, radius and component sizes use even numbers from the scales (space/*, radius/*, text styles). No odd values.

004

One primary action per screen Recommended

Use one Primary button for the main action. Secondary actions use Outline or Neutral; low-emphasis actions (“Skip”, “Cancel”) use Text or Text Neutral. Lg (48) is the default size on mobile.

005

Small buttons keep a 48 tap area Mandatory

Xs (24) and Sm (32) buttons are for dense, secondary places only. In Flutter they must still have a 48×48 touch target (MaterialTapTargetSize.padded or extra hit padding).

006

Inputs: Label above by default Recommended

Use the “Label above” input style everywhere. Use “Material” only where vertical space is tight, and only on bg/screen (its floating-label cutout is painted with bg/screen).

007

Status: never colour alone Mandatory

Every status tone has two tokens: surface and text. The text colour is also used for that tone's icon and border. Always pair the colour with a label or icon so it is clear without colour.

008

Contrast Mandatory

Text ≥ 4.5:1 and icons/borders ≥ 3:1 against their background, in both Light and Dark. Disabled states are exempt. Check any new token pair before adding it.

009

Typography & languages Mandatory

English uses Roboto. Gujarati and Hindi use Noto Sans Gujarati / Noto Sans Devanagari at the same size and line height. Prefer Regular and SemiBold; use Bold sparingly. Avoid 10px (Button/Xs) for Gujarati labels.

010

Icons Mandatory

Material Symbols Rounded, weight 400, on a 24 grid. A new icon component must keep its shape layer named “Icon” so colour overrides survive icon swaps. Flutter: material_symbols_icons → Symbols.<name>_rounded.

011

Extending the system Recommended

New colour → add a primitive, then a Color token (Light + Dark values), then use the token. New component → bind only Color tokens, space/* and radius/*, and existing text styles. Add component-specific tokens only when a component truly needs its own colour.

Do and don't

One primary action

Do. Give the main action the Primary style and the others a quieter one.
Don't. Put two Primary buttons side by side. People can't tell which one matters.

Status with a label

PresentAbsent
Do. Name the status in the badge so it reads without colour.
Don't. Use coloured dots alone. Colour-blind members and screen readers lose the meaning.

Label above inputs

Do. Keep the label visible above the field.
Don't. Use the placeholder as the only label. It disappears as soon as someone types.

Behaviour

A static design can't show these, so they are part of the spec.

TopicBehaviour
Tap targetsEvery tappable element keeps a 48 × 48 touch area, including Xs/Sm/Md buttons and the close icon. AppTheme sets MaterialTapTargetSize.padded; custom widgets add hit padding.
Dark mode primaryFilled primary buttons are #3FA5F9 with dark text (textOnPrimary), not white. Never hard-code white on primary.
Theme switchingFollow the system setting (ThemeMode.system). Never pick colours by checking brightness; read context.colors.
ScrimDialogs and bottom sheets use bgScrim as barrierColor (50% in Light, 70% in Dark). AppTheme sets it for sheets; pass it to showDialog.
Single-select sheetNo buttons. Tapping an option selects it and closes the sheet.
Multi-select sheetApply is disabled and Clear hidden until at least one option is selected; Clear empties the selection.
Bottom sheetsAdd the device safe-area inset at the bottom, scroll long lists inside the sheet and cap height at about 90% (isScrollControlled: true).
Material inputsOnly on the screen background; the floating-label cut-out is painted with bgScreen.
Text overflowSingle-line labels truncate with an ellipsis (buttons, tabs, option rows); body text wraps.
LanguagesTest every screen with Gujarati and Hindi strings; they run longer and taller than English.

Changing the system

Figma is the source of truth; code and this site follow it.

  1. Change it in FigmaUpdate the variable, text style or effect style in the Figma file. Never change a value only in code.
  2. Regenerate the themeExport tokens.json and run the generator. The Dart files are marked GENERATED; don't edit them by hand.
  3. Replace lib/theme/Widgets built on tokens update with no other code changes.
  4. Update this siteRebuild it from the same tokens.json and upload the folder again, so the documented values always match the app.

A missing token or component is a design question, not a code workaround. Raise it with Mag before adding a one-off value.
