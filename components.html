Button

Five variants in four sizes, each with Default, Pressed and Disabled states (60 variants in Figma). Leading and trailing icons are optional.

Text Neutrallabel text/secondaryfill bg/surfacelabel text/disabled

Usage

  • One Primary button per screen for the main action (Rule 004). Secondary actions use Outline or Neutral.
  • Text and Text Neutral are for low-emphasis actions such as “Skip” and “Cancel”. Dialogs and sheets pair Text Neutral Md with Primary Md.
  • Lg is the default on mobile. Xs and Sm are for dense secondary places and still need a 48 × 48 tap area (Rule 005).
  • Long labels truncate with an ellipsis. Avoid Xs for Gujarati labels; 10 px is too small for the script.
Dart
AppButton(
  label: 'Mark attendance',
  variant: AppButtonVariant.primary, // primary, outline, neutral, text, textNeutral
  size: AppButtonSize.lg,            // xs, sm, md, lg
  leadingIcon: Symbols.how_to_reg_rounded,
  onPressed: markAttendance,         // null = disabled
)

Usage

  • Use Label above everywhere (Rule 006). Use Material only when vertical space is tight, and only on bg/screen.
  • Labels can be hidden (Show label off) when the context is obvious, as in a search field; keep an accessible label in code.
  • Error helper text says what is wrong and how to fix it.
Dart
AppTextField(
  style: AppTextFieldStyle.labelAbove, // or .material
  label: 'Mobile number',
  prefix: '+91',
  hint: 'Enter your number',
  helperText: "We'll send a code to this number",
  errorText: phoneError,              // switches to the Error state
  keyboardType: TextInputType.phone,
)

Spec

Padding 8 × 2, radius 4, Label 12/18 text, optional 14 px icon with a 4 px gap. The icon is off by default.

Usage

  • Badges are read-only. They are not buttons and do not react to taps.
  • Always keep the text label. Colour alone never carries the meaning (Rule 007).
  • Keep labels to one or two words.
Dart
StatusBadge(
  label: 'Live now',
  tone: StatusTone.error, // neutral, info, success, warning, error, pending, progress
  showIcon: false,
)

Usage

  • Use a dialog only for a decision or an important result. For choices, use a bottom sheet.
  • Primary action names the result (“Leave”, “Register”), not “OK” or “Yes”.
  • Dialogs are not themed globally: pass barrierColor yourself.
Dart
final leave = await showDialog<bool>(
  context: context,
  barrierColor: context.colors.bgScrim,
  builder: (_) => AppDialog(
    icon: AppDialogIcon.none,          // info, success, warning, error
    title: 'Leave without saving?',
    body: 'Your changes to this event will be lost.',
    primaryLabel: 'Leave',
    secondaryLabel: 'Stay',            // Text Neutral Md
  ),
);

  • Use sheets for choices and short tasks that keep the screen in context.
  • Add the device safe-area inset at the bottom; long lists scroll inside the sheet.
  • Show the search field when there are more than about seven options.
Dart
final mandal = await showModalBottomSheet<String>(
  context: context,
  isScrollControlled: true, // lets the sheet grow to ~90% height
  builder: (_) => AppBottomSheet.singleSelect(
    title: 'Choose mandal',
    options: mandals,
    selected: current,
    showSearch: true,
  ),
);
// Scrim, top radius and drag handle come from AppTheme.

Usage

  • Use 2 to 4 tabs of equal width. Labels are one or two words and truncate with an ellipsis.
  • Underline tabs switch between sections of the same page. Segmented tabs filter one list.
  • Use the arrow keys to move between tabs; in Flutter both widgets support this out of the box.
Dart
// Underline
TabBar(tabs: const [Tab(text: 'Details'), Tab(text: 'Attendees'), Tab(text: 'Photos')])

// Segmented
SegmentedButton<EventFilter>(
  segments: const [
    ButtonSegment(value: EventFilter.upcoming, label: Text('Upcoming')),
    ButtonSegment(value: EventFilter.live, label: Text('Live')),
    ButtonSegment(value: EventFilter.past, label: Text('Past')),
  ],
  selected: {filter},
  showSelectedIcon: false,
  onSelectionChanged: (s) => setState(() => filter = s.first),
)
